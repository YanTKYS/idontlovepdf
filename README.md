# idontlovepdf

自治体内で一般職員が利用することを想定した「PDF編集ツール」。

PDFの処理は、同一開発者による別リポジトリ `YanTKYS/idontlovepdf-engine` が担当する。

| リポジトリ | 責務 |
|---|---|
| `idontlovepdf`（本リポジトリ） | 一般職員向けPDF編集ツールのUI / UX |
| `idontlovepdf-engine` | PDF解析・暗号化認証／復号・本文抽出・検索・置換・保存 |

## 現在の段階

**試作版。PDFの文字を検索し、1件ずつ置き換え、変更前と編集中のPDFを見比べて、編集済みPDFとして保存できる。**

`idontlovepdf-engine` v0.2.1 の正式Release bundleを同梱し、次の操作を一般職員向けの画面として提供する。

1. PDFを選択する
2. 直したい文字を検索する
3. 検索結果から1件を選ぶ
4. 新しい文字を入力する
5. 置換する
6. 変更前／編集中のPDFプレビューで結果を確かめる
7. 編集済みPDFを保存する

利用者がPDFの内部構造を理解する必要はない。画面にはPDF内部の情報（object番号、テキストの分割単位、フォント名等）を出さない。

確認できている範囲は「動作確認」の項に記載する。GitHub PagesとIISでの動作は未確認である。

## 判定

技術的実現性と運用可否は分けて扱う。

| 区分 | 判定 | 根拠 |
|---|---|---|
| 技術的実現性 | **あり** | 自作browser engineによる実PDF検証で、本文抽出・日本語ToUnicode・暗号化PDF・複数の描画単位にまたがる語句の検索・置換／保存まで確認済み |
| 運用可否 | **未判定** | 複数の実PDFで動作したことと、一般職員が安定運用できることは別である |

検討の経緯と根拠は `docs/feasibility.md` に記録している。

## できること / できないこと

現時点でできること。

- PDFファイルを選択する（ボタン、またはドラッグ＆ドロップ）
- ブラウザ内でPDFを読み込み、本文テキストを認識する
- 本文の文字を検索する（部分一致）。PDF内部で複数の描画単位に分かれて記録されている語句も、続いた1つの文字列として検索できる
- 検索結果から1件を選んで置き換える
- 分かれて記録されている語句を、同じ文字数の語句へ置き換える
- 文字を削除する（置き換える文字を空欄にする）
- 変更前のPDFと編集中のPDFをその場でプレビューし、切り替えて見比べる
- 成功した置換の内容を、変更履歴として画面で確認する
- 編集済みPDFを `元の名前.edited.pdf` として保存する
- パスワード保護されたPDFで、パスワードを入力して開く
- エラーの内容を区分して表示する（パスワード、非対応形式、破損、フォント 等）

現時点でできないこと。

- 任意のPDFを自由に編集すること（下の「編集できない場合」を参照）
- 「すべて置換」
- PDF上の文字を直接クリックしての編集、文字位置やフォントの変更
- ページ回転・ページ挿入・ページ削除
- スキャンPDF（画像だけのPDF）の編集

### 文字数が変わる置き換えについて

PDFの中では、1つの語句が複数の描画単位に分かれて記録されていることがある。日本語の文書ではよくある形である。

この場合、文字の位置はもとの文字数を前提に記録されているため、**文字数が変わる置き換えを行うと、文字の並びがずれる**。本ツールはずれたPDFを作らない方針とし、次のとおり扱う。

| 置き換え | 分かれて記録されている語句 | 1つの単位に収まっている語句 |
|---|---|---|
| 同じ文字数へ置き換える | できる | できる |
| 空欄にして削除する | できる | できる |
| 違う文字数へ置き換える | **できない** | できる |

できない場合は、置換を実行する前に画面へ、

> この箇所は現在、同じ文字数への置換または削除に対応しています。

と表示し、「置換」ボタンを押せない状態にする。文字数を合わせるか、元のファイル（Word等）からの修正を検討する。

### 編集できない場合

次の場合は、検索まではできても編集結果を保存できない。画面にその旨を表示する。

| 場合 | 画面の案内 |
|---|---|
| パスワード等で暗号化されたPDF | 暗号化PDFの保存には現在対応していません |
| 文書側で変更が禁止されているPDF | 文書側で変更が制限されています |
| PDFのフォントに無い文字へ置き換えようとした | この文字は置き換えられません |

いずれの場合も、元のファイル（Word等）からの修正を検討する。

## 構成

```text
index.html                     ツール本体
css/style.css                  画面のスタイル
js/app.js                      画面とエンジンの接続
vendor/idontlovepdf-engine.js  idontlovepdf-engine v0.2.1 の正式Release bundle
vendor/README.md               取り込んだengine versionと更新手順
docs/feasibility.md            実現可能性の検討記録
reference/guide_context.md     開発ガイド `lg_toolkit_guide` の最小ガイド（参照用）
.nojekyll                      GitHub PagesでJekyll処理を無効化する（後述）
```

npm、Node.js、esbuild、webpack、Vite、Parcel等のビルド環境は本リポジトリへ導入していない。

`idontlovepdf-engine` 側で生成済みのブラウザ向け1ファイルbundleを、そのままES Moduleとして読み込む。最終構成は静的ファイルのみである。

### エンジンとの責務分担

検索と置換の対象を決める処理は、すべてengineの公開APIへ任せている。

| 処理 | 担当 |
|---|---|
| PDFの解析、テキストの分割単位の判断、語句の検索（`searchText()`） | engine |
| 検索結果1件の置換（`replaceTextMatch()`）、保存（`save()`） | engine |
| 画面表示、操作の順序、置換の安全確認、プレビュー、変更履歴 | 本リポジトリ |

本リポジトリでは、PDFの描画命令の解釈、テキストの分割単位の連結、object番号の参照といったPDF内部構造の判断を行わない。

## 外部依存・通信

- 実行時に外部通信は発生しない。
- 外部CDN、外部フォント、外部API、ライセンスサーバー、analyticsのいずれも利用しない。
- PDFプレビューはブラウザ標準のPDF表示機能とBlob URLだけで行う。PDF.js等の追加ライブラリも、外部のPDFビューアサービスも利用しない。
- エンジンbundleはリポジトリへ同梱している。実行時にGitHub Releaseから取得する方式は採らない。
- 選択したPDF、入力した検索文字・置換文字・パスワードは、いずれもブラウザ内だけで扱う。サーバーへ送らない。

## 個人情報・機密情報の取り扱い

- PDFの内容、検索文字、置換文字を送信・保存しない。
- 変更履歴は画面に表示するだけで、localStorage、sessionStorage、IndexedDB、cookieのいずれにも保存しない。PDFを選び直すと消える。
- 入力したパスワードは処理中のメモリ内だけで扱う。同じくどこにも保存しない。
- パスワードや暗号鍵を画面へ表示せず、ログにも出力しない。

## 利用環境

静的HTTPサーバーからの配信を前提とする。

- GitHub Pages
- IIS等の庁内静的Webサーバー（閉域運用を含む）

配置は、リポジトリの内容をそのまま公開ディレクトリへ置くだけでよい。サーバー側の設定要件は次の1点である。

- `.js` をJavaScriptのMIME type（`text/javascript` 等）で配信すること（IISの既定設定で満たされる）

GitHub Pagesでは既定でJekyllが動作し、`vendor/` ディレクトリが公開対象から除外される。これを避けるため、リポジトリ直下に `.nojekyll` を置いている。**削除しないこと。**

PDFプレビューはブラウザ標準のPDF表示機能を利用する。この機能が無効な環境では、プレビュー欄に案内を表示し、検索・置換・保存はそのまま利用できる。

### `file://` での直接起動について

`index.html` を `file://` で直接開く方式は、正式な運用形態としない。

ES Moduleはブラウザのセキュリティ制約により `file://` から読み込めないためである。この場合は画面上に案内を表示する。

## 使い方

1. 静的HTTPサーバー経由で `index.html` を開く
2. 「PDFを選択」からPDFを選ぶ（ドラッグ＆ドロップも可）
3. 状態表示が「成功」になり、認識した本文の件数とPDFプレビューが表示される
4. 「検索する文字」に直したい文字を入れて「検索」を押す
5. 検索結果から直したい1件を選ぶ（前後の文章で見分ける）
6. 「置き換える文字」に新しい文字を入れて「置換」を押す
7. プレビューが「編集中」へ切り替わるので、直った内容を確認する
8. 「編集済みPDFを保存」を押してダウンロードする

補足。

- 置き換える文字を空欄にして置換すると、選択した文字を削除できる。
- 置換は1件ずつ行う。置換のたびに同じ検索文字で検索し直すので、残りの件数を確認しながら進められる。
- プレビューの「変更前」「編集中」は何度でも切り替えられる。「変更前」は最初に選んだPDFそのままである。
- 「変更 N件」は、編集中のPDFへ実際に反映された置換の件数である。失敗した置換や、同じ文字への置換は数えない。
- 元のPDFファイルは変更しない。保存は `元の名前.edited.pdf` という別名で行う。
- パスワード保護されたPDFでは、まず空パスワードでの読み込みが自動的に試される。それで開けない場合のみパスワード入力欄が表示される。

## エンジンの更新

`vendor/README.md` の「engineの更新手順」を参照する。要点は次のとおり。

1. `idontlovepdf-engine` で新versionをRelease
2. Release asset `idontlovepdf-engine.js` を取得
3. `.sha256` と照合
4. `vendor/idontlovepdf-engine.js` を差し替え
5. `ENGINE_VERSION` の表示を確認
6. `idontlovepdf` 側で実ブラウザ回帰確認

engine versionは `vendor/README.md` で管理する。JavaScriptコードへ版数を書き写さない。実行時のversion表示にはbundleがexportする `ENGINE_VERSION` を使う。

## 既知の制約

- GitHub Pages / IIS 上での動作は未確認（「動作確認」を参照）。
- 複数の描画単位に分かれて記録されている語句は、同じ文字数への置き換えと削除だけができる（「文字数が変わる置き換えについて」を参照）。
- 置換は1件ずつ行う。「すべて置換」は用意していない。
- 検索結果の表示は先頭100件まで。件数は全件を表示するが、それ以降を選ぶには検索する文字を長くして絞り込む。
- プレビューは確認用である。プレビュー上の文字を直接編集したり、置換した箇所へ自動でスクロールしたりはしない。
- 暗号化PDFの再保存はengine側で未対応。
- engine v0.2.1 の公開APIでは `/P` permission（読み取り可否・変更可否）を事前に取得できないため、編集を試みた時点で結果を案内する。
- スキャンPDF（画像のみのPDF）は本文テキストを持たないため対象外。
