2判断が変わった理由

このリポジトリで最も重要な情報。一度「運用困難」と判断した後、調査範囲を広げて判定を変更した。

初回

OSS中心の検討

  1. PDF.js / pdf-lib 等のOSS JavaScriptライブラリを中心に調査
  2. 表示・生成・テキスト追加・注釈・フォーム入力は可能
  3. 既存PDF本文の直接編集は、事実上レイアウトエンジンの自作が必要で困難
  4. 運用困難と判断
再検討

商用SDKまで範囲拡大

  1. 「既存ライブラリ利用前提でも本当に不可能か」を再確認
  2. OSSに限らず、商用JS/WASM SDKまで調査範囲を拡大
  3. 既存本文を直接編集できるSDKが製品機能として存在することを確認
  4. 実現可能性ありへ変更

「以前の判断が間違っていた」という話ではない。 OSS中心の調査範囲では、実際に運用困難だった。

調査範囲を商用JS/WASM SDKまで広げたことで、実現可能性が見つかった。 初回判定は「調査範囲に対しては正しかったが、調査範囲そのものが狭かった」と整理する。

ただし、ここで変わったのは技術的実現性の見通しであって、庁内での運用可否ではない。 運用可否は依然として未判定である。

今後「できない」と判断するときは、それが技術の限界か、調査範囲の限界かを必ず区別する。

3候補比較

「本文直接編集」は、既存PDF内の文字を選択して修正・削除・置換できることを指す。 テキスト追記、注釈追加、白塗り＋重ね書きは含めない。

候補 本文直接編集 静的Web適合 費用 現在の扱い
PDF.js × 不可 ○ 適合 OSS 表示用途
pdf-lib × 不可 ○ 適合 OSS 今回の主目的には不適
Apryse WebViewer ○ 可 ○ 適合 商用 第一候補
Foxit PDF SDK for Web ○ 可 ○候補 要確認 商用 第二候補
  • PDF.js の「×」について: PDF.js は表示・テキスト抽出には適している。「不可」なのは既存本文の書き換えであって、PDF表示ができないという意味ではない。
  • pdf-lib の「×」について: pdf-lib はPDF生成、ページへの描画、テキスト追加、フォーム入力には使える。既存本文の文字を選択して差し替える用途に向かない、という意味である。
  • Foxit の「○候補」について: 編集機能は存在するが、静的配信のみで完結する構成にできるかを実配置で確認していないため、断定していない。
  • 「商用」について: 両SDKとも本番利用には製品ライセンスが必要。Apryse の Content Edit は追加ライセンス対象とされる。 価格は公式な確認が取れていないため記載しない。

4何がまだ分からないか

重要なのは「機能一覧」ではなく、実際の自治体業務で扱うPDFで正常に編集できるかである。 以下はいずれも実機検証を行っていない。

  • 未確認日本語PDFの実編集品質
  • 未確認埋め込みフォントへの対応
  • 未確認編集後PDFの互換性（別ビューア・印刷）
  • 未確認外部通信・ライセンス認証の要否
  • 未確認オフライン・庁内配置の条件
  • 未確認ライセンス費用・調達条件
  • 未確認一般職員向けUIとして成立するか

「機能が存在する」ことと「庁内で一般職員向けツールとして運用できる」ことは同じではない。 上記が未確認である限り、本番実装へは進まない。
